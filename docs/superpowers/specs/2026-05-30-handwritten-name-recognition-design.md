# 手寫姓名辨識設計：OCR 輔助 + 可選雲端 VLM 建議 + 人工確認 + 校正學習閉迴圈

**Date:** 2026-05-30
**Status:** Draft (brainstorming approved; pending spec review)

---

## 背景與問題

OCR→JSON→XLSX 管線已可在 400 DPI 下辨識服務紀錄表的 `service_date`、`identity`、`gender`、
`medical_record_no`，但**手寫姓名**是唯一仍未解、且最關鍵的欄位（認錯姓名＝認錯病人）。

拿參考表單 `tests/fixtures/pdf/for testing only.pdf` 的姓名區放大核對後確認：

- 姓名是**行書連筆中文**（正確答案「葉心安」由使用者確認），壓在印刷格線/標籤上。
- PaddleOCR PP-OCRv5（mobile / server）為印刷/場景文字而訓練，對這種連筆姓名**先天讀不出**。
- 即使最強的雲端 vision 模型，也只能給出「**像是**葉心安」的合理猜測，**無法保證 100%**。
- 醫療場景姓名**零容錯**：任何模型自動產出的姓名都不應被無條件採信。

結論：正確設計不是追求「全自動 OCR 姓名」，而是 **OCR 輔助 → 可選 VLM 建議 → 人工確認**，
並以**校正學習閉迴圈**讓系統越用越準、越少依賴雲端。

## 目標

- 為姓名欄位提供可靠的擷取流程：產出最佳建議供人工確認，姓名**永不**未經人工確認即入庫。
- 可選的雲端 VLM「name agent」只接收**個資最小化的姓名局部裁圖**，產生建議。
- agent 由 **config file 指定**；**不存在 / 未啟用 / 連不上 / 出錯時，完全不影響既有流程**。
- 建立**校正資料收集**與**本機確認姓名名冊 + 模糊比對**的閉迴圈。

## 非目標（YAGNI，留待之後）

- 本機 VLM 後端與多後端可插拔（v1 只做雲端 VLM）。
- 訓練/微調本機手寫模型。
- 把近期校正範例當 few-shot 餵給 VLM（名冊模糊比對先做為核心閉迴圈）。
- 重寫完整審核 UI（沿用既有審核/手動編輯流程；姓名以「待確認」標記與建議值承載）。
- 自動辨識病人限定欄位（國籍/年齡/管道/疾病狀態/來源/癌別）與 A 區諸勾選——非本案範圍。

## 架構

清楚切分「離線」與「雲端」邊界：

| 元件 | 位置 | 職責 | 純度 / 可測 |
| --- | --- | --- | --- |
| A. 姓名裁圖 | 離線 PaddleOCR 外掛 | 由 OCR 錨點幾何裁出「姓名/病歷號：」之後那一行手寫姓名，**排除病歷號數字列與診斷日**；輸出裁圖檔並在 record metadata 記錄路徑 | 幾何純函式可測；影像 I/O 在外掛 |
| B. Name Agent（可選） | 主程式 | 由 config 指定的雲端 VLM adapter，輸入姓名裁圖 → 回傳建議姓名（＋備選/信心）；缺席即 no-op | 介面以假 agent 測；真呼叫手動驗證 |
| C. 校正資料收集 | 主程式 | 人工確認/修正落成 append-only JSONL 紀錄 | 純 IO，可測 |
| D. 名冊 + 模糊比對 | 主程式 | 已確認姓名累積成本機名冊；OCR/agent 候選對名冊模糊比對（difflib）推薦最接近者 | 純 stdlib，可測 |
| 整合 | 主程式 | 組合建議（agent + 名冊）→ 標 `name.unconfirmed` → 人工確認 → 寫 store + 更新名冊 | 假 agent 驅動可測 |

離線外掛維持離線；雲端呼叫只發生在主程式的 B，且為可選。

## 資料流

```
PDF → 離線外掛 OCR/打勾
        → record（identity/gender/medical_record_no/service_date 已填；name 留空）
        → 額外輸出「姓名裁圖」並記錄其路徑
   → [主程式] 名冊模糊比對（先試本機名冊）
        → 命中夠接近 → 直接給建議（不需雲端）
        → 否則且 agent 已設定 → 呼叫雲端 VLM(裁圖) → 建議
   → record.name = 建議（若有），標 warning `name.unconfirmed`
   → [人工確認/修正]（既有審核流程）
   → 寫入 XLSX；並把 {裁圖, OCR原始, agent建議, 名冊建議, 最終值, 欄位, record_id, 來源頁, 時間}
     寫入 correction store + 更新名冊
```

agent / config 缺席時：跳過 B（且名冊空時 D 亦 no-op），record 與既有流程完全不變。

## Config（指定 agent）

一個獨立 config file（例如 `name_agent.yaml`，路徑可由環境變數或 CLI 參數指定）：

```yaml
enabled: true
provider: claude            # v1 僅支援雲端 VLM provider
model: <model-id/tier>
endpoint: <api endpoint>
prompt: |
  讀出圖片中的手寫中文姓名，只回傳姓名本身。
```

- API key 走環境變數，不寫入 config / 不入庫。
- 檔案不存在、`enabled: false`、或 provider 無法初始化 → agent 停用（流程不受影響）。

## 個資 / 隱私

- 只把**姓名那一行**的裁圖送給雲端 agent，**排除病歷號（亦屬個資）、診斷日與其他欄位**。
- 校正 store 與名冊存於**本機**；名冊長大後可在本機命中、減少送出本機的次數。
- 文件需明確標示：啟用雲端 agent 會把姓名裁圖傳出本機。

## 錯誤處理 / 優雅可選

- agent 未設定/停用/初始化失敗/呼叫逾時或錯誤 → 視為「無建議」，record.name 留空、標 `name.unconfirmed`，流程照常。
- 名冊不存在/為空 → 模糊比對 no-op。
- 任何學習層（C/D）寫入失敗 → 記為 warning，不阻斷主流程。

## 測試策略

- **裁圖**：對參考表單驗證裁出的是「姓名行」且**不含病歷號數字**；幾何函式以合成 bbox 單元測試。
- **Name Agent 介面**：以**假 agent**（回固定建議）測整合流程；CI 不連網、不需金鑰。
- **缺席優雅性**（最重要）：無 config → record 不變、不崩。
- **config 解析**：enabled/停用/缺檔分支。
- **校正 store**：寫入/讀回一筆校正紀錄。
- **名冊模糊比對**：合成名冊下，近似候選命中正確姓名、過遠則不命中（含相似度門檻邊界）。
- **最弱級距評估（spike）**：把真實姓名裁圖送候選級距（先 Claude）看誰讀得出「葉心安」，記錄結果以定預設級距。此為手動 / optional marker，不進預設 CI。

## 成功準則

- [ ] 離線外掛能輸出僅含姓名的裁圖（不含病歷號），並在 record 記錄路徑。
- [ ] 可選 name agent 介面就緒：有設定時對裁圖產生姓名建議；無設定/不可用時流程完全不受影響。
- [ ] 姓名一律標 `name.unconfirmed`，需人工確認後才入庫。
- [ ] 人工確認/修正會寫入 correction store 並更新本機名冊。
- [ ] 名冊模糊比對能對近似候選推薦正確的已確認姓名（純 stdlib，CI 可測）。
- [ ] 既有測試與 policy 全綠；雲端真呼叫僅手動 spike 驗證。

## 風險與緩解

| 風險 | 機率 | 影響 | 緩解 |
| --- | --- | --- | --- |
| 連筆姓名連最強 VLM 也讀錯 | 高 | 高 | 設計即假設不可全自動：一律人工確認；agent 只給建議 |
| 裁圖誤含病歷號造成個資外送 | 中 | 高 | 裁圖排除病歷號列；測試驗證裁圖內容；可預設停用雲端 agent（opt-in） |
| 名冊模糊比對誤推相近姓名 | 中 | 高 | 設相似度門檻；仍需人工確認；推薦而非自動採用 |
| 雲端 agent 變更/中斷 | 中 | 低 | 優雅可選，缺席不影響流程 |
| 單一樣本過擬合裁圖座標 | 中 | 中 | 用 OCR 錨點幾何而非固定像素；之後以更多樣本校正 |
